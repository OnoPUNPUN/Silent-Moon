# 📚 Silent Moon — Personal Reading Library (Go Backend)

> A lightweight, secure, and synchronization-focused REST API powering a cross-platform, local-first digital reading ecosystem.

---

## 1. Architecture & Tech Stack

- **Runtime**: Go 1.24+
- **HTTP Routing**: Chi v5 with modular structured middleware (slog logger, recovery, CORS, compression)
- **Database**: PostgreSQL 16 (Neon / Self-hosted)
- **Query Layer**: Type-safe queries generated by `sqlc` using `pgx/v5`
- **Database Migrations**: `golang-migrate` embedded directly in the application binary
- **Object Storage**: Cloudflare R2 (S3-compatible via AWS SDK for Go v2) with direct client presigned upload/download URLs
- **Authentication**: Argon2id/bcrypt password hashing, short-lived JWT access tokens, rotated refresh tokens linked to registered devices
- **Synchronization Engine**: Monotonic append-only sequence log (`sync_changes`), push/pull workflows with client cursor tracking, operation idempotency, and optimistic version conflict detection

## 3. Quick Start

### Prerequisites
- Go 1.24+
- Docker & Docker Compose (optional for local PostgreSQL)

### Running with Docker Compose
```bash
docker compose up -d
```
This spins up PostgreSQL on port `5432` and boots the API server on port `8080`, applying embedded database migrations automatically on startup.

### Running Locally
1. Copy the environment configuration:
   ```bash
   cp .env.example .env
   ```
2. Run database migrations and start the server:
   ```bash
   go run ./cmd/api
   ```
3. Run tests:
   ```bash
   go test -v ./...
   ```

## 5. Synchronization Flow

1. **Local Writes**: The Flutter application commits modifications immediately to local SQLite.
2. **Push Batch**: When online, the client pushes queued operations with unique `operationId`s to `/api/v1/sync/push`.
3. **Optimistic Concurrency**: If an entity's version on the server is higher than the client's `baseVersion`, a `conflict` is returned.
4. **Append Change Log**: Accepted mutations generate monotonic `sync_changes` entries.
5. **Incremental Pull**: Other devices pull changes past their last known cursor via `/api/v1/sync/changes?cursor=123`.
6. **Tombstones**: Soft deletions emit delete change records so all offline devices receive tombstones upon reconnection.
